# Workspace

## Overview

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **API framework**: Express 5
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run API server locally

See the `pnpm-workspace` skill for workspace structure, TypeScript setup, and package details.

## Project: Plan 0 — Model Orchestrator & Source Harvester

### Purpose
Harvest free AI model endpoints daily from the GitHub repo `zebbern/no-cost-ai`, test them
(link health, latency, throughput, quality), rank them, maintain a registry of the top active
endpoints, and expose a smart router. Plan 1 (trading agent) will consume this registry later.

### Artifacts
- `artifacts/api-server` (Express 5, mounted on `/api`) — harvester pipeline + REST API
- `artifacts/orchestrator` (React + Vite + Tailwind v4 + shadcn/ui + recharts + wouter, mounted on `/`) — operator dashboard
- `artifacts/mockup-sandbox` (component preview) — unused for this product

### Database tables (`lib/db/src/schema`)
- `models` — registry (latency, tps, success_rate, quality, score, rank, status, type, endpoint, ...)
- `harvest_runs` — every pipeline run (status, stage, progress, totals, message)
- `model_history` — per-run snapshot of each model's metrics for time-series

### Status enum
`ACTIVE` / `SLOW` / `FAIL` / `ARCHIVED`. Type enum: `chat / embedding / completion / image / audio / unknown`.

### Score formula (in `artifacts/api-server/src/lib/harvester/scoring.ts`)
`0.35 * (200/latency_ms) + 0.30 * min(tps,100)/100 + 0.20 * success + 0.15 * quality`,
clamped to `[0, 1]`.
- `SLOW` if latency > 3000ms or score < 0.25
- `FAIL` if link unreachable
- `FAIL` rows older than 7 days are auto-archived.

### Pipeline stages (`artifacts/api-server/src/lib/harvester/orchestrator.ts`)
`discovering` → `testing` → `benchmarking` → `ranking` → `finalizing`. Capped at 80 endpoints
per run, concurrency 8 for health checks and 6 for benchmarks. Live in-memory status object
exposed via `GET /api/harvest/status`.

### Scheduler
Runs on every 12-hour interval after server start. See `harvester/scheduler.ts`. The next
scheduled timestamp is exposed via `/api/stats` and `/api/harvest/status`.

### Routes (in `artifacts/api-server/src/routes/`)
- `GET /api/healthz`
- `GET /api/models` (filter, sort, paginate) / `GET /api/models/top` / `GET /api/models/active` / `GET /api/models/:id` (with history)
- `GET /api/runs` / `GET /api/runs/latest`
- `POST /api/harvest/run` / `GET /api/harvest/status`
- `POST /api/route` (taskType: realtime | analysis | balanced | embedding)
- `GET /api/stats`

### Frontend pages (`artifacts/orchestrator/src/pages`)
`dashboard.tsx`, `models.tsx`, `model-detail.tsx`, `runs.tsx`, `router.tsx`. All hooks come
from `@workspace/api-client-react` (generated by Orval from `lib/api-spec/openapi.yaml`).

### Notes
- UI in English; no emojis.
- Source URL: `https://raw.githubusercontent.com/zebbern/no-cost-ai/main/README.md` and the
  whole repo tree (markdown + code) is crawled via the GitHub Contents API.
- Set `GITHUB_TOKEN` in env for higher GitHub rate limits if desired.
- Plan 1 (trading agent) will be built on top of this; the harvester data is consumed there.

## Project: Plan 1 — Institutional Gold (XAU/USD) Trading Agent

### Purpose
Paper-trading control room for a single operator on XAU/USD. Consumes a real-time market intelligence feed and applies a deterministic rules engine + a "two-key" AI confirmation (two Plan 0 chat models must agree) before any signal is allowed to execute. Supports OFF / MANUAL / AUTO execution modes and DAILY / MID trading modes.

### Artifacts
- `artifacts/api-server` — extended with the trader engine, routes, and scheduler (same Express server, mounted on `/api`)
- `artifacts/trader` (React + Vite + Tailwind v4 + shadcn/ui + recharts + framer-motion + wouter, mounted on `/trader`) — Arabic RTL operator cockpit

### Data source
`https://source-bootstrap--wenat95130.replit.app/intelligence` (signal, market, levels, news, timing, traps, divergence, macro, cot) plus `/macro`, `/cot`, `/mode`. Modes: DAILY (atrMult 1.8, R:R 1.8, 300s expiry); MID (atrMult 1.3, R:R 1.5, 180s expiry). Override base via `SOURCE_BASE_URL`.

### Database tables (`lib/db/src/schema/trader.ts`)
- `trader_settings` (singleton) — execution mode, trading mode, risk profile, AI confirmation requirements
- `trader_account` (singleton) — paper balance, equity, drawdown, daily/total counters
- `trader_snapshots` — every market snapshot pulled from the source
- `trader_signals` — every proposed signal with its rules + AI audit trail
- `trader_positions` — open and closed paper positions
- `trader_equity_curve` — point-in-time equity samples for the dashboard chart
- `trader_cycle_state` (singleton) — last/next cycle metadata, running flag

### Engine (`artifacts/api-server/src/lib/trader/`)
- `datasource.ts` — fetches `/intelligence`, `/macro`, `/cot`, `/mode` and normalizes a TraderSnapshot
- `account.ts` — singleton account read/write, daily reset, drawdown
- `rules.ts` — 13 deterministic gates ordered: exec_on → source_live → directional → confidence → atr_sane → timing_ready (not BUILDING) → cot_filter (blocks aligned EXTREME) → rr_min → daily_loss_cap → max_open → max_trades_day → no_dup_direction
- `ai-confirm.ts` — calls 2 Plan 0 chat models via OpenAI-compatible `/chat/completions`, temperature 0, expects single-line JSON `{"vote":"BUY|SELL|NEUTRAL","reason":"..."}`. Non-conforming = ABSTAIN. Both must agree on direction.
- `sizing.ts` — position size = (riskPct% × equity) / |entry − SL|
- `positions.ts` — open/close logic, exit reasons (SL/TP/MANUAL), realized + unrealized PnL
- `executor.ts` — full cycle: snapshot → exit-check existing positions → rules → AI confirm → sizing → AUTO/MANUAL/REJECT
- `scheduler.ts` — auto-loop on the active mode's interval (DAILY 300s, MID 180s)

### Routes (in `artifacts/api-server/src/routes/trader.ts`)
- `GET /api/trader/account` / `POST /api/trader/account/reset`
- `GET /api/trader/settings` / `PATCH /api/trader/settings`
- `GET /api/trader/snapshot`
- `GET /api/trader/signals` (status filter) / `GET /api/trader/signals/:id` (full audit)
- `POST /api/trader/signals/:id/approve` / `POST /api/trader/signals/:id/reject`
- `GET /api/trader/positions` / `POST /api/trader/positions/:id/close`
- `POST /api/trader/cycle/run` (manual cycle trigger)
- `GET /api/trader/dashboard` (aggregated dashboard payload)

### Frontend pages (`artifacts/trader/src/pages`)
`dashboard.tsx`, `signals.tsx`, `signal-detail.tsx` (gates + AI votes audit), `positions.tsx`, `settings.tsx`, `not-found.tsx`. Layout shell in `components/layout.tsx` with global execution-mode control and "تشغيل دورة الآن" button. All hooks come from `@workspace/api-client-react`.

### Notes
- UI is **Arabic RTL** with a dark institutional gold/graphite palette. Cairo + JetBrains Mono fonts. **No emojis** anywhere.
- Defaults: executionMode=OFF, tradingMode=DAILY, risk 1%/trade, dailyLossCap 3%, maxOpen 2, maxTradesDay 5, minConf 0.6, minRR 1.3, requireAiConfirmation=true, aiConfirmCount=2, signalExpiry 300s.
- Singleton rows use `id="singleton"` for trader_settings / trader_account / trader_cycle_state.
- The Plan 0 orchestrator at `/` is independent and untouched. Trader is a separate product on `/trader`.
